# Execution and benchmark methodology

Portable Release uses `-O3` without silently adding `-march=native`. For each immutable case, the worker computes the oracle outside the timed path, checks each algorithm's output before timing, warms the execution path, and times batched operations (up to the documented iteration/output-retention limits). Every output in a timed batch is validated after the clock stops; any mismatch invalidates the *entire* timing. The declared timing includes algorithm-side allocation but excludes input generation and oracle validation. It currently includes storing completed results in the batch, a known allocator/cache perturbation that is explicitly documented and must be considered in comparisons.

The parent uses a dedicated worker binary, versioned checksummed input frames, a bounded response and total deadline, Linux process-group kill/reap and resource limits where applicable. ASan builds deliberately cannot use ordinary `RLIMIT_AS` because of virtual shadow mappings. Worker crashes, timeouts, plugin errors and OOM statuses are recorded as censored failures, not wins. Hardware cycle/instruction counters are optional and unavailable by default; missing readings must not be forged.

A/B timing uses randomized balanced `ABBA` / `BAAB` block order, with order and seed retained in each raw row. Case-level medians and independent holdout are the basis of inference; individual timed batches are **not** independent cases. The `ablate` command runs the same requested discovery case budget with grid, random, stratified and feedback-adaptive proposals, and reports *actual* case counts and seconds; empirical CPU times differ and are not guaranteed equal. Synthetic threshold localization has known ground truth, real algorithm data do not.

To reproduce the acceptance command surface use `bash scripts/acceptance_smoke.sh` (requires `jq` for assertions only). The test suite covers adversarial comparisons, malformed IPC, plugin fault injection, null/synthetic calibration, scaling model fits, replay tampering and minimization. For cross-machine claims, independently measure hardware/governor/thermal/cache context; don't extrapolate beyond the measured n/density/k ranges.

Standalone `reproduce` source prints an illustrative single-run duration only to demonstrate execution. Use the native bounded, balanced, independently confirmed experiment pipeline for any performance claim; do not compare such exported witness timings to the SQLite protocol.
